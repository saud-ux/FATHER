# مسابقة الخلايا — كل الملفات في جذر واحد

فك الضغط وارفع الملفات نفسها مباشرة على فرع `main`. لا ترفع مجلدًا خارجيًا يجمعها. كل ملفات المصدر في هذا الملف المضغوط موجودة في الجذر، دون أي مجلدات.

هذه نسخة مستقلة من أحدث اللعبة: واجهة مبسطة بلهجة عامية، لوحة ٥×٥ بصفوف تحت بعضها، وأسئلة وصور المرفقات. لا تُربط الأسئلة بالخلايا.

## الرفع على GitHub

1. أنشئ مستودعًا **Private** لأن الملفات فيها إجابات المسابقة وصور الأصدقاء.
2. فك ضغط ZIP وافتح المجلد الناتج.
3. من GitHub اختَر Add file ثم Upload files.
4. حدّد الملفات نفسها وارفعها مباشرة، ثم احفظها على `main`.
5. عند فتح الريبو يجب أن ترى `package.json` و`worker.ts` و`README.md` في الصفحة الأولى.

رفع الملفات إلى GitHub يحفظ المصدر فقط. لتعمل اللعبة والمزامنة بين الجوال واللابتوب، جهّز الاستضافة كما يلي. GitHub Pages وحده لا يشغّل خادم اللعبة أو حفظ الصور.

## تجهيز الاستضافة مرة واحدة — للمساعد التقني

يلزم Node.js 24 أو أحدث، وحساب Cloudflare يدعم Workers وD1 وR2. تفعيل R2 قد يتطلب إعداد فوترة لدى Cloudflare؛ راجع ما يعرضه حسابك قبل التفعيل.

من جذر المشروع:

```sh
npm install
npx wrangler login
npx wrangler d1 create majlis-game
npx wrangler r2 bucket create majlis-game-images
```

انسخ `database_id` الذي يعيده أمر إنشاء القاعدة وضعه بدل `00000000-0000-4000-8000-000000000000` في `wrangler.jsonc`. احتفظ باسمي الربط `DB` و`BUCKET`. إذا غيرت اسم القاعدة أو مخزن الصور فغيّره في الإعداد أيضًا.

أنشئ جدول الجلسات **مرة واحدة**، ثم انشر:

```sh
npm run db:remote
npm run deploy
```

افتح رابط Workers الذي يظهر بعد النشر. التحديثات اللاحقة تحتاج `npm run deploy`، دون إعادة إنشاء الجدول.

للتجربة المحلية، بدل أوامر النشر:

```sh
npm run db:local
npm run dev
```

لتشغيل الاختبارات:

```sh
npm test
```

أوامر التجهيز تولّد مجلدات `node_modules` و`dist` و`.wrangler` تلقائيًا. هذه مجلدات تشغيل وليست موجودة داخل ZIP ولا تحتاج ترفعها إلى GitHub. لا ترفع ملفات `.env` أو `.dev.vars` أو مفاتيح حسابك.

## طريقة اللعب لأبوي

1. افتح اللعبة على اللابتوب واضغط «ابدأ لعبة جديدة».
2. انسخ رابط المقدّم وافتحه بالجوال. الرابط فيه التحكم والإجابات؛ خلّه لك لحالك.
3. وصّل اللابتوب بالبروجكتر بوضع تكرار الشاشة. اضغط «ابدأ اللعب على اللابتوب»، وبعدها «كبّر الشاشة».
4. من الجوال افتح «الأسئلة»، اختَر سؤال واضغط «ورّهم السؤال».
5. تبي تعرض الحل؟ اضغط «ورّهم الجواب» وأكّد.
6. ارجع للوحة، اختَر خلية، واضغط «اعطها» للفريق اللي جاوب صح.
7. ما عرفوا الجواب؟ خلّ الخلية فاضية وخذ سؤال ثاني. غلطت؟ اضغط «تراجع».

الأزرق يصل اليمين باليسار، والأحمر يصل الأعلى بالأسفل. الأضلاع المتصلة هي اللي تنحسب، والفوز يظهر تلقائيًا. جولة جديدة تفضّي اللوحة وتحفظ الانتصارات والأسئلة اللي سألناها. تغيير الأسماء والاتجاهات وإضافة الأسئلة من الإعدادات.

## الحفظ والخصوصية

الجهازان يحتاجان إنترنت. المزامنة كل ١٫٥ ثانية تقريبًا إضافة إلى زمن الشبكة. الجلسات محفوظة في D1 والصور في R2، وتحديث الصفحة ما يصفّر اللعب. الأوامر المتعارضة لا تُنفذ فوق بعضها، والضغط المتكرر لا يحسب الفوز مرتين.

رابط الجمهور وحده ما يعطي التحكم أو بنك الإجابات. الإجابة لا تصل لشاشة الجمهور إلا بعد أمر صريح من المقدّم. الصور والإجابات مضمنة في `questions.ts` للخادم فقط، وليست ضمن ملفات المتصفح العامة.

**فرق الاستضافة:** هذه الحزمة المستقلة لا تحتوي بوابة تسجيل حساب ChatGPT التي تحمي الموقع الأصلي. صلاحية المقدّم هنا محمية بمفتاح رابط الجلسة. صفحة البداية متاحة لمن يعرف رابط الاستضافة، ويمكنه إنشاء جلسة منفصلة. إذا أردت تقييد دخول الموقع كله، جهّز Cloudflare Access على مستوى الاستضافة. لا تشارك رابط المقدّم.

لا توجد داخل الملفات بيانات الجلسات الفعلية أو روابط المقدّم السرية. بيانات الموقع المنشور حاليًا لا تنتقل تلقائيًا إلى الاستضافة الجديدة. صور وأسئلة المرفقات موجودة، أما التعديلات التي أجريتها داخل جلسة فعلية فتبقى على استضافتها الأصلية.

## المحتوى والاختبار

البنك ١٩ سؤالًا: ١٧ جاهزة وسؤالان محجوبان للمراجعة، هما بداية سؤال اجتماع ينبع المقطوعة وإجابة سؤال الذهب غير الواضحة. إجابات الصور من تأكيد المستخدم، دون استنتاج أسماء من الوجوه، ولا اشتراط لحرف الإجابة.

فُحص بناء الواجهة و١٤ اختبارًا لمنطق اللعبة و٢٥ اختبارًا للخادم باستخدام SQLite ومخزن صور اختباري. أُخذت الواجهة والمنطق من أحدث النسخة المنشورة. هذه الحزمة المستقلة لم تُنشر إلى حساب Cloudflare الخاص بك؛ يلزم تجربة الجوال والبروجكتر والاتصال بعد تجهيز الاستضافة.

## الملفات

- `app.tsx`: الواجهة والتحكم وإضافة الأسئلة.
- `styles.css` و`index.html`: التنسيق وصفحة البداية.
- `core.ts`: الخلايا والجوار والفوز والتراجع.
- `service.ts`: صلاحيات المقدّم والحفظ والمزامنة والصور.
- `questions.ts`: الأسئلة والصور والإجابات، للخادم فقط.
- `worker.ts`: مسارات الخادم والملفات العامة.
- `build.mjs`: بناء واجهة المتصفح.
- `schema.sql` و`wrangler.jsonc`: الجدول وإعداد الاستضافة.
- `test-core.ts` و`test-api.mjs`: اختبارات المشروع.
- `package.json` و`.gitignore`: الحزم وأوامر التشغيل واستبعاد الملفات المحلية.
